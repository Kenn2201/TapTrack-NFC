# TapTrack NFC v1.2.0 RC — Production QA Roadmap

This is the final roadmap from completed implementation to human acceptance.

## Current position

- Milestones A–G: engineering complete.
- Drizzle automatic production migrations: implemented.
- Automated CI: required before master promotion.
- Production-human QA: pending.
- Release remains `v1.2.0 RC`.
- NFC-001 is the protected primary validation card and must not be lifecycle-modified, rewritten, rotated, reissued, or replaced.

## H — Automatic database migration gate

Deployment now runs Drizzle migrations before the Render API begins listening.

Drizzle adopts the pending v1.2 database work:

1. Event visibility — project migration 008.
2. NFC request queue + one-ACTIVE-card guard — project migration 009.
3. Anonymous public feedback — project migration 010.

Migration 007 is intentionally excluded because it is already applied to production Neon.

**Expected outcome:** the Render deployment succeeds and the API starts only after the schema is ready.

If migration 009 reports duplicate ACTIVE cards, stop. Do not auto-repair them and do not change NFC-001.

## I — Production event QA

Human QA on the deployed main/master environment:

- Create PUBLIC event.
- Create INVITE_ONLY event.
- Search/select required participants.
- Invited USER sees invite-only event.
- Uninvited USER does not see it.
- ADMIN and OPERATOR can operate it.
- No RSVP Accept/Decline workflow remains.
- Public-event absence does not reduce Attendance Rate.
- Closed invite-only required event contributes to Attendance Rate.
- Zero eligible required events shows **No required events yet**.

## J — NFC/card QA

Use disposable cards for lifecycle testing:

- My Card setup request.
- My Card replacement request.
- Duplicate open request blocked.
- Admin request queue.
- PENDING → IN_REVIEW → FULFILLED / REJECTED.
- One user cannot end normal workflows with two ACTIVE cards.
- ACTIVE → LOST / REVOKED / DISABLED.
- Replacement workflow.

Do not perform destructive tests on NFC-001.

## K — iPhone regression QA

Regression-check the already physically validated flow:

- Public card tap → Safari `/t` → fragment sanitized → safe resolve → no attendance.
- ADMIN/OPERATOR selects exact OPEN session.
- Enable iPhone Attendance Mode.
- Physical tap records NFC URL attendance into that session.
- Duplicate tap reports Already Recorded and creates no duplicate.

## L — Android physical acceptance

Still pending until a compatible Android Chromium device is tested:

- NDEFReader availability.
- Direct physical Web NFC scan.
- Shared attendance engine.
- Duplicate protection.
- URL fallback when direct Web NFC is unavailable.

Do not mark Android physical Web NFC as passed before this test.

## M — Auth/account QA

- Sign in / Register / Forgot Password / Reset Password.
- Change Password: wrong current, mismatch, short, valid.
- Real users are unaffected by honeypot fields.
- USER / OPERATOR account archive requires typing ARCHIVE.
- Archive disables sign-in and preserves history.
- ADMIN self-archive is blocked.
- Administrator can reactivate an archived account.

## N — Feedback QA

- Authenticated feedback submission.
- Anonymous `/feedback/public` submission.
- Public rate limit is stricter than authenticated feedback.
- Admin triage can distinguish anonymous and authenticated submissions.
- Page/category/reproduction context is readable.

## O — UI/responsive QA

Desktop, iPhone Safari, and small Android:

- light / dark / system theme
- AuthShell
- AuthenticatedShell desktop navigation
- mobile bottom navigation
- AdminShell
- What's New
- Release Notes / Terminology / Privacy / Terms
- profile inline editing
- Activity Pulse
- My Card / request queue
- operator console
- email preview / templates
- maintenance confirmation
- no one-character focus regression
- no white screen
- no accidental horizontal overflow
- reduced-motion behavior

## P — QA fixes

Any finding from I–O is fixed in the same repository, then CI is rerun.

## Q — Final documentation

Before release acceptance:

- README
- CHANGELOG
- VERSIONING
- deployment documentation
- compatibility documentation
- NFC flow documentation
- local `node generate-vault.cjs` when the working copy is available

## R — Human acceptance / release

After the user completes production QA:

1. Fix remaining findings.
2. Run final CI.
3. Keep production smoke checks green.
4. Remove the RC label only after explicit acceptance.
5. Create `v1.2.0` tag and GitHub Release.
6. Mark LIVE.

Until step 4, the product remains `v1.2.0 RC`.
